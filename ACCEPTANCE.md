- `tests/booking-engine.test.ts`:
  1. Атомарное предотвращение конфликтов: отказ при повторной записи на тот же бокс в то же время.

  4. Блокировка бокса: сервисный блок запрещает запись клиентов.

  6. Идемпотентность: повторная отправка формы не создает дубликатов.
  7. Исторический снимок цены: изменение прайса в каталоге не меняет цену ранее сделанной записи.
  8. Разделение финансов: выручка по завершенным работам отдельно от реально внесенных денег.

## 🔌 Оставшиеся внешние зависимости для Production

Для перевода системы в боевой режим с внешними сервисами потребуются следующие учетные данные (локально всё работает через встроенные механизмы):

1. **Supabase Production Project**:
   - `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` для подключения облачной Postgres базы данных.
   - `SUPABASE_SERVICE_ROLE_KEY` для выполнения Edge Functions.
2. **OpenAI API Key (по желанию владельца, после первых продаж)**:
   - `LLM_API_KEY`: Ключ OpenAI или совместимого провайдера для диалогов в свободной форме. Без ключа работает встроенный Intent Router.
3. **Web Push VAPID Keys**:
   - `VAPID_PUBLIC_KEY` и `VAPID_PRIVATE_KEY` для доставки системных Web Push на мобильные устройства и десктоп. При отсутствии доступен экспорт `.ics` в Календарь.
4. **Домен на Cloudflare / Vercel**:
   - Привязка собственного домена для публикации статического билда из `dist`.
