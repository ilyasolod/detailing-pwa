# Полный технический аудит системы (FINAL_TECHNICAL_AUDIT.md)

**Дата аудита:** 1 ноября 2026 г.  
**Проект:** Detailing Center Multi-Tenant PWA  
**Версия окружения:** React 19.3.1, TypeScript 7.0.2, Vite 8.3.5, Supabase PostgreSQL 15, Node.js v20.

---

## 1. Резюме аудита

Система представляет собой мультитенантную платформу для автоматизации записи в детейлинг-центры. Архитектура построена на разделении публичной витрины (`/c/:slug`) и панели управления студией (`/c/:slug/admin`). Серверная часть базируется на PostgreSQL в Supabase с активным Row Level Security (RLS) и инкапсулированными `SECURITY DEFINER` RPC-функциями.

В ходе полного комплексного аудита архитектуры, фронтенда, базы данных и инфраструктуры выявлены ключевые зоны внимания, структурированные по степени критичности (P0–P3).

## 3. Детальный анализ подсистем

### 3.1. Архитектура и маршрутизация
- **Разделение витрины и бэкенда:** Маршрут `/c/:slug` предназначен строго для клиентов конкретной студии. Маршрут `/c/:slug/admin` предназначен строго для администратора конкретной студии. Прямой переход между арендаторами без повторной аутентификации строго запрещён.
- **Отказоустойчивость:** При недоступности сервера отображаются специализированные экраны ошибки с кнопками повторной попытки (`WifiSlash`). В продакшен-режиме локальный `LocalStorage` демо-фоллбек принудительно отключён (`isLocalModeAllowed()`), исключая отображение фиктивных данных.
- **Обработка неизвестного slug:** Возвращается честный статус «Студия не найдена» (honest 404).

### 3.2. База данных и безопасность (PostgreSQL & RLS)
- Все таблицы (`companies`, `services`, `weekly_schedule`, `schedule_breaks`, `gallery_photos`, `blocked_intervals`, `bookings`, `company_admins`) защищены RLS (`ENABLE ROW LEVEL SECURITY`).
- `SECURITY DEFINER` функции имеют фиксированный `SET search_path = public`, что полностью защищает от атак подмены схем (search_path hijacking).
- Конкурентная запись защищена транзакционной блокировкой `pg_advisory_xact_lock(hashtext(p_company_id::text))`.
- Услуги проверяются на принадлежность именно компании, в которую оформляется запись (`WHERE company_id = p_company_id AND id = ANY(p_service_ids) AND active = true`).
- Временные интервалы строго проверяются на пересечение с рабочим временем, обеденными перерывами студии, блокировками администратора и подтверждёнными/активными бронями (`tstzrange && tstzrange`).

### 3.3. PWA и Service Worker
- В манифесте объявлены `name`, `short_name`, `theme_color`, `background_color`, `display: standalone`.
- Service Worker компилируется через `vite-plugin-pwa` в режиме `injectManifest` из `src/sw.ts`.
- Реализована предварительная очистка устаревших кэшей (`cleanupOutdatedCaches()`).
- Кэширование слотов и RPC исключено, что гарантирует абсолютную свежесть данных о доступных интервалах времени.
