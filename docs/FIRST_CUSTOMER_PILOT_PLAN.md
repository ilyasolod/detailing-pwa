## 1. Анализ готовности конфигурации

### 1.1. Что уже полностью подготовлено в кодовой базе (100% готовность)
1. **Чистая DDL-схема базы данных:**  
   Файл `supabase/production_schema.sql` (89 КБ) содержит полное описание структуры (миграции 001, 002, 003, 005, 006, 007, 008) без тестовых компаний (`Detail Lab`, `Auto Studio`) и без фиксированных демо-UUID.
2. **Конфигурация хостинга Vercel:**  
   Файл `vercel.json` содержит SPA fallback (`/(.*) -> /index.html`), запрет кэширования для Service Worker (`sw.js`, `registerSW.js` -> `max-age=0, must-revalidate`), долгосрочный кэш для хешированных ассетов (`max-age=31536000, immutable`) и базовые security-заголовки.
3. **PWA-манифест и Service Worker:**  
   В `vite.config.ts` настроен манифест («Detailing PWA», theme color `#0A0A0C`, display `standalone`). В `src/sw.ts` настроен Workbox: запросы к API Supabase, мутации и приватные данные администратора **не кэшируются**, утечка данных между студиями исключена.
4. **Параметризация корневого тенанта:**  
   Поддержана переменная `VITE_DEFAULT_COMPANY_SLUG`, позволяющая перенаправлять посетителей с корня домена (`https://domain.kz/`) на витрину первого клиента без правок кода.
5. **Безопасность переменных окружения:**  
   В `.env.example` зафиксированы только публичные переменные `VITE_*`. Секретный ключ `service_role` полностью исключён из фронтенда.
6. **Тестовое покрытие:**  
   65/65 unit-тестов Vitest, 0 ошибок TypeScript, оптимизированные чанки сборки (< 274 КБ), Playwright E2E-тест пройден.

### 1.2. Что требуется выполнить вручную инженеру
- Создать проект в Supabase Cloud;
- Накатать `production_schema.sql` через SQL Editor;
- Настроить Auth (Site URL, Redirect URLs);
- Создать первого пользователя-владельца и привязать к компании;
- Подключить репозиторий в Vercel и задать Environment Variables;
- Настроить DNS-записи домена;
- Провести smoke-тесты со смартфона.

## 2. Развёртывание Supabase Cloud

### Шаг 2.1. Создание проекта `[Supabase Dashboard]`
1. Перейдите на [https://supabase.com/dashboard](https://supabase.com/dashboard) и войдите в аккаунт.
2. Нажмите кнопку **«New Project»** (в рамках вашей организации).
3. Заполните поля формы:
   - **Name:** `detailing-pwa-prod`
   - **Database Password:** сгенерируйте надёжный пароль (20+ символов через менеджер паролей). *Сохраните пароль в защищённом хранилище!*
   - **Region:** выберите `Frankfurt (eu-central-1)` (оптимальный пинг до Казахстана и СНГ ~70–90 мс).
   - **Pricing Plan:** `Free` (для первого пилота) или `Pro` (для автоматических ежедневных бэкапов).
4. Нажмите **«Create new project»** и дождитесь завершения инициализации базы данных (1–2 минуты).

### Шаг 2.2. Применение чистой схемы БД `[Supabase Dashboard]`
1. В левом меню проекта перейдите в раздел **SQL Editor**.
2. Нажмите **«New query»**.
3. Откройте локальный файл `supabase/production_schema.sql`, скопируйте его содержимое полностью и вставьте в окно SQL Editor.
4. Нажмите кнопку **«Run»** (или сочетание `Ctrl+Enter`).
5. Убедитесь, что запрос завершился успехом: `Success. No rows returned`.
6. Выполните экспресс-проверку наличия таблиц:
   ```sql
   SELECT tablename, rowsecurity FROM pg_tables WHERE schemaname = 'public' ORDER BY tablename;
   ```
   *Ожидается:* 9 таблиц, у всех `rowsecurity = true`.

### Шаг 2.3. Настройка аутентификации (Auth Settings) `[Supabase Dashboard]`
1. Перейдите в **Authentication -> URL Configuration**:
   - **Site URL:** укажите итоговый адрес приложения (например, `https://detailing-app.kz`).
   - **Redirect URLs:** добавьте строку `https://detailing-app.kz/**`.
   - Нажмите **«Save»**.
2. Перейдите в **Authentication -> Providers -> Email**:
   - Убедитесь, что провайдер **Email** включён.
   - Опция **«Confirm email»**: для пилотного запуска с одним владельцем рекомендуется оставить включённой (поскольку учётная запись администратора будет создана вручную через панель с флагом Auto-Confirm).

### Шаг 2.4. Получение API-ключей `[Supabase Dashboard]`
1. Перейдите в **Project Settings -> API**.
2. Скопируйте и сохраните:
   - **Project URL:** вид `https://xxxxxxxxxxxxxxxxxxxx.supabase.co`
   - **anon public key:** длинный JWT-токен из блока `Project API keys` (тег `anon public`).

> [!CAUTION]
> **СТРОЖАЙШИЙ ЗАПРЕТ:**
> Ни при каких обстоятельствах не копируйте и не вставляйте ключ `service_role secret` в настройки фронтенда или Vercel!

## 3. Развёртывание на Vercel

### Шаг 3.1. Подключение репозитория `[Vercel Dashboard]`
1. Перейдите на [https://vercel.com/dashboard](https://vercel.com/dashboard).
2. Нажмите **«Add New...» -> «Project»**.
3. Выберите ваш GitHub-репозиторий с проектом Detailing PWA.

### Шаг 3.2. Настройка параметров сборки `[Vercel Dashboard]`
В блоке **Build and Output Settings** проверьте параметры:
- **Framework Preset:** `Vite`
- **Root Directory:** `./`
- **Build Command:** `pnpm build`
- **Output Directory:** `dist`
- **Install Command:** `pnpm install`

### Шаг 3.3. Настройка переменных окружения (Environment Variables) `[Vercel Dashboard]`
В блоке **Environment Variables** добавьте следующие 4 переменные (для окружений `Production`, `Preview`, `Development`):

| Имя переменной | Значение | Пояснение |
|----------------|----------|-----------|
| `VITE_SUPABASE_URL` | `https://xxxxxxxxxxxxxxxxxxxx.supabase.co` | Скопированный URL из шага 2.4 |
| `VITE_SUPABASE_ANON_KEY` | `eyJhbGciOiJIUzI1NiIsInR5c...` | Публичный анонимный ключ из шага 2.4 |
| `VITE_APP_URL` | `https://detailing-app.kz` | Рабочий домен сервиса |
| `VITE_DEFAULT_COMPANY_SLUG` | `prime-detailing` | Slug первой пилотной студии |

Нажмите кнопку **«Deploy»**. Дождитесь успешного завершения сборки (обычно ~45–60 секунд).

### Шаг 3.4. Привязка домена и HTTPS `[Vercel Dashboard]` + `[Панель DNS]`
1. В панели Vercel откройте **Settings -> Domains**.
2. Введите ваш домен (например, `detailing-app.kz` или поддомен `app.client-detailing.kz`) и нажмите **«Add»**.
3. Vercel предоставит необходимые DNS-записи:
   - Для поддомена: запись типа `CNAME` со значением `cname.vercel-dns.com`.
   - Для корневого домена: запись типа `A` со значением `76.76.21.21`.
4. Войдите в панель управления регистратора вашего домена (Cloudflare, GoDaddy, Hoster.kz и др.) и внесите указанные записи.
5. После обновления DNS (от 2 до 30 минут) Vercel автоматически выпустит бесплатный SSL-сертификат Let's Encrypt. Статус домена станет зеленым (`Valid Configuration`).

## 4. Онбординг первого пилотного клиента (Студии)

### Шаг 4.1. Сбор данных у клиента `[Опрос клиента]`
Запросите у владельца студии точную информацию:
1. Официальное название центра (например, `Prime Detailing Almaty`);
2. Желаемый уникальный slug для прямой ссылки (например, `prime-detailing`);
3. Рабочий номер WhatsApp для получения заявок (в международном формате, например, `77011234567` — без плюса);
4. Физический адрес студии (например, `г. Алматы, пр. Достык, 180`);
5. Рабочий график студии: время открытия, закрытия, выходные дни и обеденные перерывы;
6. Email владельца для входа в панель управления;
7. Базовый прайс-лист: список услуг, стоимость «от», длительность выполнения в минутах;
8. Модель расписания: подтвердить, что запись ведётся на один основной детейлинг-пост (Single Bay Model).

### Шаг 4.2. Создание учётной записи владельца `[Supabase Dashboard]`
1. В панели Supabase перейдите в **Authentication -> Users**.
2. Нажмите кнопку **«Add user»** -> **«Create user»**.
3. Заполните:
   - **Email:** email владельца студии (например, `owner@prime-detailing.kz`);
   - **Password:** сгенерируйте стойкий криптографический пароль (не менее 16 знаков с буквами разного регистра, цифрами и спецсимволами через менеджер паролей);
   - Отметьте флажок **«Auto Confirm User»** (чтобы вход работал сразу без подтверждения по почте).
4. Нажмите **«Create user»**.
5. Скопируйте полученный **User UID** (например, `a1b2c3d4-e5f6-7a8b-9c0d-1e2f3a4b5c6d`).

## 6. Диагностика потенциальных проблем (Troubleshooting Guide)

| Симптом / Ошибка | Вероятная причина | Способ диагностики и решения |
|------------------|-------------------|-------------------------------|
| `CORS Error` или `Failed to fetch` при открытии сайта | Неверный URL Supabase в переменных Vercel | Проверьте `VITE_SUPABASE_URL` в Vercel Settings -> Environment Variables. URL должен иметь формат `https://<ref>.supabase.co` без слэша на конце. После изменения запустите Redeploy. |
| При обновлении страницы (F5) на `/c/prime-detailing` ошибка `404 Not Found` | Отсутствует SPA fallback | Убедитесь, что в корне репозитория присутствует файл `vercel.json` с блоком `rewrites: [{ "source": "/(.*)", "destination": "/index.html" }]`. |
| `relation "companies" does not exist` в логах | Не была применена схема базы данных | Откройте SQL Editor в Supabase и выполните скрипт `supabase/production_schema.sql`. |
| Владелец не может войти в панель администратора: `Неверный логин или пароль` | Пароль скопирован с пробелом или не привязан admin-пользователь | 1. Проверьте в `Authentication -> Users`, что пользователь существует.<br>2. Проверьте запрос: `SELECT * FROM company_admins WHERE user_id = '<USER_UID>';`. Если записи нет, выполните `INSERT INTO company_admins`. |
| Ссылка WhatsApp не открывает диалог | В номере WhatsApp указан знак `+`, скобки или дефисы | В поле `whatsapp_number` таблицы `companies` номер должен храниться **строго в цифровом формате** без пробелов и плюса: `77011234567`. Исправьте через `UPDATE companies SET whatsapp_number = '77011234567' WHERE slug = 'prime-detailing';`. |
| При бронировании ошибка: `Selected time slot is already booked` | Слот занят другой активной бронью или неистёкшим hold-окном (30 мин) | Это штатное поведение защиты от овербукинга. Если запись тестовая, отмените её из админки или подождите 30 минут для автоматического освобождения слота. |
| Браузер на смартфоне не предлагает установить PWA | Сайт открыт по HTTP, либо отсутствует SSL | PWA работает **строго по протоколу HTTPS**. Убедитесь, что Vercel завершил выпуск SSL-сертификата (зеленый статус домена). |
| Ошибка: `column "slot_duration_minutes" of relation "companies" does not exist` | Использован старый устаревший шаблон SQL | В актуальной схеме шагом слотов управляет логика `get_available_slots` (30 мин). Поле `slot_duration_minutes` исключено из SQL-шаблона онбординга. Используйте скрипт из раздела 4.3 данного плана. |

## 7. Регламент резервного копирования в Production

### 7.1. При использовании Supabase Free Tier
Поскольку на бесплатном тарифе автоматические бэкапы отключены, настройте еженедельный экспорт данных:
```bash
# Выполняется инженером локально через Supabase CLI:
pnpm dlx supabase db dump --db-url "postgresql://postgres:[PASSWORD]@db.[REF].supabase.co:5432/postgres" --data-only -f backups/prod_backup_$(date +%Y%m%d).sql
```

### 7.2. При переходе на Supabase Pro Tier
В панели Supabase перейдите в **Database -> Backups** и убедитесь, что активны ежедневные снапшоты (глубина хранения 7 дней).
