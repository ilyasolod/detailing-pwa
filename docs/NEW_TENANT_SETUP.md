# Инструкция по подключению нового детейлинг-центра (NEW_TENANT_SETUP.md)

Это пошаговое руководство для администратора платформы по регистрации и онбордингу нового детейлинг-центра (тенанта) в системе.

---

## 1. Концепция многотенантности (Multi-Tenancy)

Каждый детейлинг-центр изолирован на уровне:
- Базы данных PostgreSQL: все таблицы содержат `company_id uuid REFERENCES companies(id)`.
- Политик безопасности (RLS): доступ к данным компании строго ограничен через связь `auth.uid() -> company_admins.user_id -> company_id`.
- URL-маршрутизации:
  - Клиентская витрина: `/c/<slug>` (например, `/c/prime-detailing`);
  - Кабинет владельца: `/c/<slug>/admin`.
- Настроек оформления (дизайн, логотип, фирменный цвет, WhatsApp).

> [!IMPORTANT]
> **Ограничение модели расписания (Single Bay Model):**
> Версия v1.0 рассчитывает свободные слоты исходя из модели одного поста обслуживания (одна машина в боксе одновременно). Убедитесь, что пилотный детейлинг-центр работает по такой схеме, либо выделяет под онлайн-запись свой главный детейлинг-пост.

---

## 2. Пошаговый процесс онбординга

### Шаг 1. Создание учётной записи владельца в Supabase Auth
Владелец студии авторизуется по email и надёжному паролю.

В панели Supabase Studio (`Authentication -> Users`) создайте учётную запись:
- **Email:** рабочий email владельца студии;
- **Password:** сгенерированный стойкий пароль (не менее 16 символов, не используйте стандартные тестовые пароли);
- **Auto Confirm User:** включено.

Зафиксируйте сгенерированный `user_id` (например, `a1b2c3d4-e5f6-7a8b-9c0d-1e2f3a4b5c6d`).

---

Выполните SQL-запрос для добавления детейлинг-центра:

```sql

  active

  gen_random_uuid(), -- или фиксированный UUID

```
*Зафиксируйте возвращённый `id` компании (`COMPANY_ID`).*

---

### Шаг 3. Привязка владельца к компании (`company_admins`)
Свяжите созданного пользователя из `auth.users` с компанией:

```sql
INSERT INTO company_admins (
  company_id,
  user_id,
  role
) VALUES (
  '<COMPANY_ID>',
  '<USER_ID>',
  'owner'
);
```

---

### Шаг 4. Настройка недельного графика работы (`weekly_schedule`)
График задаётся для всех дней недели (0 = Воскресенье, 1 = Понедельник, ..., 6 = Суббота):

```sql
INSERT INTO weekly_schedule (company_id, weekday, is_working, opening_time, closing_time)
VALUES
  ('<COMPANY_ID>', 0, false, '10:00:00', '18:00:00'), -- Воскресенье — выходной
  ('<COMPANY_ID>', 1, true,  '09:00:00', '20:00:00'), -- Понедельник
  ('<COMPANY_ID>', 2, true,  '09:00:00', '20:00:00'), -- Вторник
```

### Шаг 7. Проверка доступности
1. Откройте в браузере: `https://<DOMAIN>/c/prime-detailing`.
2. Проверьте:
   - Корректность названия, адреса, номера WhatsApp;
   - Загрузку каталога услуг;
   - Календарь свободных слотов (воскресенье недоступно, обеденные часы исключены).
3. Войдите в кабинет владельца: `https://<DOMAIN>/c/prime-detailing/admin`.
4. Передайте логин и пароль владельцу студии.
